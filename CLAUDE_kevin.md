## Key Methodological Details
- **`dreamlet_helper()` fixes the contrast by `case_control_levels`, not by how the column is stored (fixed 2026-09-26).** Before the fix it never set the reference level and took `coefNames()[2]`; a character arm is ordered alphabetically by the model matrix, so "case" became the reference and every log fold change came back with the wrong sign and no error. It now validates that the two levels are distinct and present, relevels to `case_control_levels[1]`, and selects the coefficient by name (`<var><case level>`), stopping if it is absent. `aggregateToPseudoBulk()` preserves the factor's level order, which is what makes releveling before aggregation sufficient.
- **`nebula_helper()` now relevels the arm by `case_control_levels` too (fixed 2026-10-09).** Before, a character arm made the coefficient `logFC_<var>control` with flipped signs, and the case-named column the scripts read did not exist. NEBULA is cell-level with a donor random effect, so the wrapper checks only the arm for donor-constancy: a cell-level numerical covariate is a legitimate adjustment there, whereas the pseudobulk wrappers must refuse it. One-level categorical covariates are dropped from the design. The helper could not previously run without covariates (one-column `pred` dropped to a vector).
- **`dreamlet_helper()` shares `build_pseudobulk()`'s validation, not its aggregation (2026-10-09).** dreamlet's `processAssays()` accepts only the object from `dreamlet::aggregateToPseudoBulk()` (per-sample cell counts and aggregation parameters live in internal slots; `processOneAssay()` is unexported), so the aggregation stays dreamlet's. The donor-level rule is shared through `.check_donor_constant_vars()`: the arm and every numerical covariate must be constant within a donor (error), while a within-donor *categorical* covariate splits the donor into one sample per level, which is what `build_pseudobulk()`'s `group.by` does too. Before this, the helper pasted *any* varying covariate onto the donor id, so a cell-level numeric silently produced a cell-level test.
- **`Seurat::AggregateExpression()` drops a grouping variable with one value** from the returned metadata ("will be ignored"). `.pseudobulk_from_seurat()` puts it back so `.prepare_pseudobulk_metadata()` can drop it from the design; without that, a single-sex cohort or a batch constant within a cell type errored with "undefined columns selected".
- **`esvd_helper()` is a pure pass-through to `eSVD2::eSVD_helper()` (fixed 2026-10-09).** eSVD2 >= 1.2.0 *refuses* with an error what it cannot fit (all-zero gene, individual with < 3 cells, arm with < 2 individuals); only its `eSVD_helper()` turns those into a filter or a warning-plus-NA, so the wrapper must not call `eSVD()` directly. The wrapper adds nothing but the old signature, a version guard, and `bool_check_donors = FALSE` as "zero every threshold except `min_ids_per_arm`" (eSVD2 errors on a one-donor arm, so that filter is what keeps the warning-plus-NA contract). All-zero genes come back with `NA` statistics and `fdr_vec = 1`, so a caller's `sum(fdr_vec < 0.05)` needs no NA handling. eSVD2 1.2.0 results differ from 1.0.1.x for every gene (nuisance cap, MLE rate, log-scale empirical null), and `report_results()` now returns `logFC_se`.
- **Unified DE table contract** (`.unify_de_results()`): columns `gene, logFC, se, pvalue, padj`, all on the log2 scale, with row names set to the genes. NEBULA's coefficients are divided by `log(2)`; dreamlet's SE is `logFC / t`. `padj` is plain BH over the non-NA p-values for every method, so DESeq2's unified padj is *not* its independent-filtering padj (that one stays in `original`). eSVD all-zero genes get NA p and padj rather than eSVD2's padding of 1, so the unified padj equals eSVD2's `fdr_vec` on the analyzed genes. A rejected eSVD cohort gives an all-NA row per gene.
- **Input contract**: `was2code_dist()` takes pre-normalized, denoised matrices. No log10, no residualization, no `var_per_cell` — all preprocessing is upstream.
- **Decomposition**: was2 distance between donor expression distributions → `was2`, `location`, `size`, `shape`. Location and size are far easier to detect than shape at small n (8 donors × 100 cells → shape tests use a 2× threshold, not 5×).
- **`was2code_permanova` returns a list**, not a vector: `pval`, `F_ob`, `F_perm` (genes × n_perm). `F_ob`/`F_perm` are deliberately exposed so a *parametric* null can be fit when empirical permutation p-values are too coarse — this is the intended path when p-value resolution limits downstream FDR.
- **NA handling**: NA distance entries go through `.calc_F_manova_na` rather than dropping genes.
- **Dependency policy**: heavy Bioconductor packages in `Suggests` with `requireNamespace()` guards, to keep `library(Was2CoDE)` quiet and fast.
- **DESeq2 already ships TOST.** `DESeq2::results(dds, lfcThreshold = T, altHypothesis = "lessAbs")` is Schuirmann's two one-sided tests verbatim (`max(p_lower, p_upper)`; DESeq2 source `R/results.R:533-539`), and DESeq2 itself errors out if `betaPrior = TRUE`. The wiki does not record this. `deseq2_tost_helper_claude.R` reimplements the arithmetic anyway — so the difference and equivalence tests share one `(lfc, se)` pair, so it is testable without Bioconductor, and so the same core works for dreamlet/NEBULA/eSVD-DE. Agreement with DESeq2 is asserted in the tests.
- **Minimum rejectable bound has a closed form**: `Delta_min = |lfc| + z_alpha * se`. TOST rejects iff `lfc_threshold` exceeds it, so the resource-based SESOI is a per-gene column (`lfc_threshold_min`), not a search.
- **Equivalence-test design rules** (from the wiki, enforced in code): unshrunken log2FC only (`lfcShrink` toward zero is anti-conservative here — simulation shows 50% shrinkage pushes the boundary rejection rate well past alpha); two explicit one-sided tests at the *full* alpha, never a 1-2alpha CI-containment check; BH across genes on the TOST p-values, no correction within a gene (intersection-union test); `lfc_threshold` mandatory, since a data-derived bound voids the type-I guarantee.
- **`independentFiltering = FALSE`** when pulling lfc/se: DESeq2's filter is tuned to the difference null and would silently change which genes can be called stable. Replaced with an explicit `base_mean_min`.
- **`R/pseudobulk.R` holds all the shared plumbing.** `build_pseudobulk()` (aggregate → re-attach donor-constant numerics → build the design), `.fit_deseq2_mle()` (design formula, `betaPrior = FALSE`, `useT`, `quiet`), `.extract_lfc_se()` (unshrunken `lfc`/`se` + `cooks_outlier`; **no p-values**). Both `deseq2_helper()` and `deseq2_tost_helper()` go through all three; they differ only in the arguments they pass and what they do with the result.
- **The TOST path is equivalence-only, by design** (Kevin, 2026-07-30). No `pvalue_diff`, no four-way partition function — just `pvalue_tost`, `padj_tost`, `equivalent`, `lfc_threshold_min`.
- **The four-way partition is a caller-side join, not a package feature**, regression-tested in `test_deseq2_tost_helper_claude.R`. `deseq2_helper()` returns `log2FoldChange` + `lfcSE`, so `deseq2_tost()` consumes them directly — **one GLM fit, and the result is bit-identical to the full `deseq2_tost_helper()` route** (DESeq2's `independentFiltering`/`cooksCutoff` only touch p-values, never the estimates). Cross `padj <= alpha` with `equivalent` for `differential` / `"significant but negligible"` / `stable` / `undetermined`.
- **`"significant but negligible"`** (renamed from `trivial`, 2026-07-30) is a real category, not an error: a precisely-estimated effect that is reliably non-zero *and* established to be below the SESOI. It is only reachable when `se < Delta/(z_{alpha/2}+z_alpha) ~= Delta/3.6`, so it is a signature of precision. Sanity check at the study level: among truly-null, precisely-estimated genes the cell fills at the difference test's false-positive rate, so compare `n_negligible` against `alpha * (n_stable + n_negligible)` — much larger means genuinely small real effects.
- **Multiplicity scale — the bug fixed 2026-07-30.** `lfc_threshold_min` was on the raw per-test scale while `equivalent` used BH-adjusted p, so they could contradict each other. `.effective_alpha()` now recovers the raw-p threshold the correction actually applied (`alpha*k/m` for BH), `deseq2_tost()` recomputes `lfc_threshold_min` there, and it is exposed as the `alpha_effective` attribute. `tost_from_estimates()` stays on the raw scale by design — it never sees the gene set.
- **Treat `padj = NA` as "not differential" when partitioning.** DESeq2's independent filter NA's the genes it declined to test (15/110 in the simulation, all low-count). Dropping them would delete exactly the `undetermined` category the partition exists to expose.
- **Non-obvious consequence**: because `padj` is no longer returned, `.extract_lfc_se()`'s `independentFiltering = FALSE` is unobservable from the return value (DESeq2's filter only ever touches `padj`). It is kept because it is still correct, and the test now asserts the real behavioral consequence — low-expression genes survive with usable `(lfc, se)` rather than being silently dropped. Non-obvious contracts pinned by its tests: `id_var` is releveled then **dropped** (donor is the unit of observation, not a design term); categorical levels are ordered by *decreasing frequency*, which is what sets each factor's reference level; constant **factors** are dropped but constant **numerics** are not; the column order is `categorical, numerical, case_control`, and case/control must stay **last** because the DESeq2 coefficient name is built from it.
- **Simulation gotcha for pseudobulk benchmarks**: a large one-directional DE fraction on a small gene panel corrupts DESeq2's median-of-ratios size factors (20/60 genes 4x up gave size factors 0.90 vs 1.12, a spurious -0.31 log2 shift on every null gene). Make simulated DE bidirectional and a minority of the panel.
