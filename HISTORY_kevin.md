### [2026-07-30] (Session 2 — TOST equivalence testing on DESeq2)
- Queried the wiki for TOST design guidance and implemented `R/deseq2_tost_helper_claude.R` + `tests/testthat/test_deseq2_tost_helper_claude.R`. 65 tests pass.
- **Key discovery: DESeq2 already implements TOST natively.** `DESeq2::results(dds, lfcThreshold = T, altHypothesis = "lessAbs")` computes exactly `max(p_lower, p_upper)` from two one-sided Wald tests (`R/results.R:533-539` in the DESeq2 source). It also refuses to run when `betaPrior = TRUE`, i.e. DESeq2 enforces the wiki's "no shrinkage" trap itself. The wiki's `[[analysis-tost-for-deg-equivalence]]` Route 1 does not mention this; the implementation is therefore mostly plumbing + partition logic, not new statistics. A unit test asserts bit-level agreement with DESeq2's `lessAbs` p-values and stat.
- **Decision: reimplement the TOST arithmetic in a standalone `tost_from_estimates()` rather than calling `results(..., altHypothesis="lessAbs")`.** Three reasons: (a) it is testable with no Bioconductor dependency; (b) the difference test and the equivalence test are then guaranteed to come from the *same* (lfc, se) pair, which `results()` called twice does not guarantee once filtering differs; (c) it generalizes to dreamlet/NEBULA/eSVD-DE unchanged, which is what Route 1's cross-method-agreement result needs.
- **New closed form worth keeping: the minimum rejectable bound is `Delta_min = |lfc| + z_alpha * se`.** TOST rejects at level alpha iff `lfc_threshold > |lfc| + z_alpha*se`, so the resource-based SESOI the wiki asks to report (`[[sesoi]]`, "smallest delta each cohort can reject") is available per gene with no search or simulation. Returned as `lfc_threshold_min`.
- **Decision: `independentFiltering = FALSE` when extracting lfc/se.** DESeq2's independent filter maximizes rejections of the *difference* null; reusing it would silently change which genes are eligible to be called stable. Replaced with an explicit, pre-specifiable `base_mean_min`.
- **Decision: `lfc_threshold` has no default.** A bound read off the data voids the type-I error guarantee (`[[sesoi]]`), so the API forces pre-specification.
- Cook's-distance-flagged genes are propagated to NA rather than kept: DESeq2 NAs the p-value but leaves lfc/se intact, so without the explicit flag an outlier-driven fit could be declared "stably expressed."
- Empirical finding (simulation): shrinking lfc by 50% raises the rejection rate at the equivalence boundary from ~0.05 to well above alpha — the anti-conservatism of `lfcShrink` in this setting is large, not marginal. Locked in as a regression test.
- **Non-obvious simulation trap, cost ~2 debug cycles.** A pseudobulk simulation with a large *one-directional* DE fraction breaks DESeq2's median-of-ratios size factors when the gene panel is small: with 20/60 genes 4x up in cases, size factors came out 0.90 (control) vs 1.12 (case), imposing a spurious -0.31 log2 shift on every null gene and turning 18/20 true nulls into "differential." Fix: make DE bidirectional and a minority of the panel. Worth remembering for any future benchmark simulation in the analysis repo, not just this test.
- Verified `use_t = TRUE` end-to-end: DESeq2 stores `tDegreesFreedom` in `mcols(dds)` and it comes out as residual df (12 donors - 2 coefficients = 10).
- Added `SummarizedExperiment` to `Suggests` (needed for `mcols()`; it is a DESeq2 dependency, so this is a formality).
- All roxygen blocks are `@noRd` so `devtools::document()` is a no-op for the new file — consistent with the other DE-method helpers being unexported. Revisit if Open Question 2 resolves toward exporting the wrappers.

### [2026-07-30] (Session 7 — multiplicity bug in lfc_threshold_min; rename "trivial")
- **Real bug found, not just a probe-script artifact.** The margins I showed last session were only in a throwaway script, but `alpha` was used in exactly two places in `deseq2_tost_helper_claude.R` and they were on *different scales*: `lfc_threshold_min` used `qnorm(1 - alpha)` (raw, per-test) while `equivalent` used `padj_tost <= alpha` (BH-adjusted). So a gene whose raw TOST p cleared alpha but whose adjusted p did not was reported as having a minimum rejectable bound inside `lfc_threshold` while being called not equivalent.
- **Why it did not show up in the existing tests**: on the simulated Seurat panel the TOST p-values are bimodal (tiny for well-expressed nulls, ~1 for DE and low-count genes), so nothing lands between the BH-attained threshold (0.0268) and the nominal 0.05. Disagreements = 0 by luck. Constructing genes with p in that band gives **12/47 disagreements**. Lesson for this codebase: the bimodal simulation cannot exercise threshold-boundary logic; such tests need hand-built `(lfc, se)` grids.
- **Fix**: new `.effective_alpha(pvalue, alpha, p_adjust_method)` recovers the raw-p threshold the correction actually applied — every `p.adjust()` method is monotone, so its rejection set is always `{p <= t}`. `deseq2_tost()` recomputes `lfc_threshold_min` at that `t`, and exposes it as the `alpha_effective` attribute. `tost_from_estimates()` deliberately stays on the raw scale (it is a single-test function that never sees the gene set) and now says so in its docs.
- For BH, `t = alpha * k / m` exactly: every rejected p is at most that, and `p_(k+1) > (k+1)alpha/m` by construction. Verified `lfc_threshold_min <= lfc_threshold` now agrees with `equivalent` gene for gene.
- **Self-correction worth recording**: my first `.effective_alpha` returned `max(p[rejected])` — the *attained* level — for all methods. That keeps the rejection set consistent but is wrong for `p_adjust_method = "none"`, where the per-gene bound must not depend on other genes. Now: `"none"` → `alpha`; BH/fdr → `alpha*k/m`; nothing rejected → `alpha/m`; anything else → attained level, documented as realized rather than nominal.
- Caveat recorded in the roxygen: `alpha_effective` is exact for the gene set as it stands, but is not a fixed constant of the design — changing `lfc_threshold` moves every p-value, hence `k`, hence `t`. So `lfc_threshold_min` answers "what bound would have flipped this gene, holding the multiplicity correction where it currently sits", not a fully self-consistent inversion.
- **Decision (Kevin): renamed the partition class `trivial` → `"significant but negligible"`.** "Trivial" read as a dismissal of what is actually an informative cell.
- Also removed a stale roxygen line on `tost_from_estimates()` still claiming it returns a two-sided Wald difference p-value (deleted two sessions ago).
- Suite: 1083 passing; the single failure was the known `test_was2code_dist.R:431` wall-clock flake.

Answer: the aggregation cannot be shared, the validation can. dreamlet's `processAssays()` accepts only the object from its own `aggregateToPseudoBulk()` — it reads per-sample cell counts (`cellCounts()`, from `int_colData`) and `metadata()$agg_pars`, and stops with "Cell counts could not be extracted" otherwise; `processOneAssay()` is not exported, so bypassing it would mean reimplementing dreamlet's pipeline.
- Probing the old helper on `.simulate_donor_seurat()` found that its "append the varying covariate to the donor id" step was a silent error path: with a cell-level numeric (`n_umi`) it made one pseudobulk sample per cell and dreamlet ran a cell-level test under a donor-level name (sign agreement 1.0, 26 genes, no error); a donor in both arms was split into two samples the same way. `build_pseudobulk()` already refused the first case via `.attach_donor_level_numerics()`.
- Decision: new shared `.check_donor_constant_vars(seurat_obj, id_var, variables)` in `pseudobulk.R`; `dreamlet_helper()` runs it on the arm and the numerical covariates (error), and still splits a donor on a within-donor *categorical* covariate, which is equivalent to `build_pseudobulk()`'s `group.by`. `build_pseudobulk()` now runs it on the arm too, since `group.by` would otherwise split a donor found in both arms into two "donors" without complaint.
- Found and fixed Bug P1 in `build_pseudobulk()`: `Seurat::AggregateExpression()` ignores a grouping variable with a single value and leaves it out of the returned metadata, so a cohort-constant categorical covariate (single-sex cohort; a batch constant within a cell type) errored with "undefined columns selected" instead of being dropped from the design. The unit test of `.prepare_pseudobulk_metadata()` passed because it built the metadata by hand. `.pseudobulk_from_seurat()` now re-attaches any dropped grouping variable. This affected `deseq2_helper()` and the TOST route on real cohorts.
- dreamlet handles a cohort-constant categorical covariate on its own (probe B ran), so no change there.

### [2026-10-09] (Session 11 — nebula_helper inspected and rewritten)
- Probed `nebula_helper()` on `.simulate_donor_seurat()` (nebula 1.5.8). Three bugs: (N1) `case_control_levels` was validated and never used, so a character arm put "case" first alphabetically, the coefficient came back as `logFC_<var>control` with every sign flipped, and the case-named column the analysis scripts read (`p_CERAD_binaryCase`, `p_AD_path_ceradTRUE`) did not exist; (N2) with no covariates `pred[order_index, ]` dropped the one-column data.frame to a vector and `model.matrix()` failed, so the helper could not run without covariates at all; (N3) a cohort-constant categorical covariate died in `model.matrix()` ("contrasts can be applied only to factors with 2 or more levels").
- Paper-track NEBULA results are presumably unaffected in sign: the scripts read the case-named column, which only exists when the arm was a control-first factor, so a character arm would have produced an error or an empty column rather than a wrong answer.
- Decision: rewritten onto the shared checks. Relevels the arm by `case_control_levels` (as dreamlet now does), runs `.check_donor_constant_vars()` on the arm only — NEBULA is cell-level with a donor random effect, so a cell-level numerical covariate (per-cell QC) is a legitimate adjustment and must stay allowed, unlike in the pseudobulk wrappers — drops one-level categorical covariates from the design, keeps `drop = FALSE` on the reorder, and builds the design with `stats::reformulate()` instead of `eval(parse())`. Added `verbose = 0` (nebula's own `verbose` was hard-coded `TRUE`); the analysis scripts do not pass it.
- Kept: `cpc = 0, mincp = 0` (every gene tested, matching the other wrappers), `offset = "nCount_RNA"`, `model = "NBGMM"`, nebula's default `ncore = 2`.
- `/code-review` flagged passing `verbose` to `nebula::scToNeb()`: nebula 1.5.8 accepts it but older versions do not, and it only guards a message the helper never triggers, so it was dropped. The review's other point (length-2 check on `case_control_levels`) is covered by `.check_donor_vars()`.
